# 候选新方案：场景文字身份验证 + 冻结 Pair-VPR

2026-09-07；**提案，尚未实现、未训练、未验证收益**。工作名 Scene-Text Identity Verification（STIV），不是已发表方法或新颖性声明。

## 1. 为什么更换信息来源

旧实验已覆盖 CLIP 全局/局部拟合、区域传播、动态屏蔽、query 条件类别偏置、FiLM、残差注入、语义 dropout、layout teacher、CLIP-based pair scoring、MNN 几何及候选扩展。aligned 多次未胜 shuffled，提示收益不能归因于正确语义；但不能断言统一根因，也不能说所有失败均来自代码错误。

新增信息应回答“这是哪家店、哪条街、哪个门牌”，而不只是“这里有楼和路”。使用实际 OCR 字符串、置信度及文字框，而不是将同一幅图再编码为 CLIP 稠密相似度。字符身份通常与类别标签不同，但仍可能重复、识别错或失效。

这是语言/场景文字信息进入 VPR，广义属于高层语义；严格说核心是文字身份匹配，不等同于语言理解、ADE 类别语义或 SemVPR 复现。

## 2. 论文依据与不能直接移植的部分

- [TextPlace，ICCV 2019](https://openaccess.thecvf.com/content_ICCV_2019/papers/Hong_TextPlace_Visual_Place_Recognition_and_Topological_Localization_Through_Reading_Scene_Texts_ICCV_2019_paper.pdf)：以自然场景文字进行地点识别和拓扑定位，支持“读取文字身份可以提供不同于外观的线索”。其结果不等价于本项目 MSLS 或冻结 Pair-VPR 增益。
- [TextInPlace，IROS 2025](https://arxiv.org/abs/2503.06501)：针对重复室内环境，结合 VPR 与 scene text spotting 双分支，筛选有判别性的文字后重排 top-K。借鉴文字筛选和候选验证，不把室内结果直接外推为室外街景有效。 [作者代码](https://github.com/HqiTao/TextInPlace)。
- [SemVPR，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Zhang_Efficient_Visual_Place_Recognition_Through_Multimodal_Semantic_Knowledge_Integration_ICCV_2025_paper.html)：训练期视觉语言教师指导局部视觉/语义描述子与聚合。新提案与其共享“额外信息帮助消除外观混淆”的目的，但不复用连续 CLIP 蒸馏；第一阶段 OCR 会有额外推理成本，不能声称无额外推理开销。

现有论文证明该方向有人探索，不证明组合本身新颖，更不保证解决本项目剩余47个错误。

## 3. 系统设计（先证明证据，再训练融合）

保留官方 Pair-VPR 的候选 top100、权重与原评分。数据库图像 OCR 一次离线缓存，查询 OCR 在线一次；原图保持统一的预注册最大分辨率，记录相对322像素基线新增计算/存储。OCR 缓存保存模型版本、权重哈希、图像哈希、原文、标准化字符、框及置信度。OCR 引擎须检查现有环境再定，不预先要求重装 torch 或新环境。

文字处理保留字符身份：Unicode 标准化、大小写和适度空白归一化，不把不同店名映射成相同的语义嵌入。数字短串、通用词和连锁品牌不能仅凭相同就判同地点。稀有度从数据库或独立训练库按图像文档频率估计，不使用查询 GT；稀有度也可能放大 OCR 错字，必须与识别置信度联合检查。

每对候选的证据包括：精确/编辑距离字符相似度、一对一文字框匹配数、数据库词频权重、双端置信度、多个字符串的相对布局。不能仅凭某一名称（例如 METREON）定位到25米内；也不把文本框布局再简化成上一轮失败的通用 token 内点计数。

**默认缺证据就弃用该分支**：查询/候选无可靠文字时保持基线；只在一边出现文字不是负证据。店铺更名、广告、施工、车辆文字都可能造成假矛盾；不自动把不相同字符串判为异地点。

## 4. 最小实验与停止顺序

### A. 覆盖率与证据审查，无模型训练

先用固定随机抽样的独立训练/开发图对检查 OCR 质量、跨视角可读性和成本，冻结配置。避免只挑当前7个失败案例。

再对开发评测集的所有查询及固定候选缓存文字，不只跑错误查询。报告：查询可靠文字覆盖、正样本跨视角共享字符覆盖、负样本重复/通用文字碰撞、无文字比例、每图耗时。全部 GT/非 GT 关系仅用于离线审计，不参与候选构造。

计算一个明示依赖 GT 的“文字可干预错误数”：必须 query 和候选内至少一个 GT 都存在按冻结规则可用的双端文字证据。它是该严格门控设计的潜在纠错上限，不是已实现纠错，也不代表所有文字方法的上限。

预先以开发集至少 +1.0 pp 为目标预算：在740查询规模上至少需要8个潜在纠错；若覆盖上限连8个都不到，则不做该严格门控方案的融合训练。8例以上仅代表未被覆盖率否决，不是 PASS。不能按检查结果逐步放松 OCR 阈值以过关。

### B. 仅在 A 未被否决时训练/校准小型证据融合器

使用与评测无重叠的地点/序列数据，训练读取固定 Pair 分数和文字证据的小融合器或文字 token 分支。原模型冻结；无证据时严格回退。其性质是多模态第二阶段验证，不是单阶段描述子创新。

对照至少包含：原 Pair；同结构无文本内容（仅框/置信度/数量）；完整 OCR；打乱字符串但保留框、数量、长度和置信度分布的匹配对照。所有组使用同样数据、步数和选模标准。后者用于区分文字身份作用与文本框形状/额外参数作用。

冻结规则后报告全体查询 R@1、纠错/误伤、触发比例、文字子集与无文字子集、速度和存储。完整 OCR 必须优于原模型及两个 matched controls，不能把子集收益当全体收益。总体 +1pp 是项目资源决策阈值，不是统计显著性定义；后续需独立集确认和配对不确定性分析。

## 5. 本提案最可能失败的原因

MSLS 的树荫、公园、高速路、低分辨率图片可能缺少文字；对应 GT 有文字但朝向不同也无用。品牌跨店重复、同一路段共用街名、门牌遮挡、OCR 将不同词识别成相同词，都会破坏判别性。此前 q653 的同地标区域错误说明即使文字相同也未必满足25m。

因此**优先验证新信息是否存在，而不是再训练一个大模型**。若 A 失败，停止此方案；若用户要求严格无 OCR 推理开销或非重排创新，则该方案不符合约束，应另行选择完整论文复现，而非继续堆 adapter。
