# 单DINO交互V2：后交互辅助监督与分组梯度限幅

## 状态

代码准备和同步，不启动真实图像smoke、训练、评测或自动队列。原V1与双编码器已完成，创新点1及这些实验的代码和权重继续保留。

## 修改依据与不变项

固定检查点诊断见`doc/SINGLE_DINO_DIAGNOSIS.md`：V1辅助读出在exchange之前，对终端交互无直接梯度；一个困难训练批上，上游投影层的已加权辅助梯度为主损失的94～124倍。当前交互只占整体描述子适配漂移的很小部分。这里只针对监督错位进行修改，不声称已找到充分因果解释。

保持单DINO、冻结创新点1、冻结原BoQ、原局部卷积/context扫描/exchange扫描/动态低秩/refine/最终输出结构不变。保留separate、aligned、permuted三组，同参数量、同seed42初值。新旧head的参数名、形状、初始张量和同权重主输出必须完全一致。

不增加ResNet、CLIP、SAM、推理参数或重排序。不增大0.025残差上限，不去空间均值，不解冻主干或BoQ。

## 修改1：将辅助读出移动到exchange之后

原版：`context/local（交互前）→ GAP → 归一化 → 辅助地点检索损失`。

V2：`两支路 → exchange（依路由交错或独立）→ 分别GAP → 归一化 → 辅助地点检索损失`。

主全局描述子计算完全不变；辅助分支只用于训练，不参与推理。辅助损失现在直接连接exchange，但仍不连接后续low-rank/fuse/refine/output，这些层继续由主检索与保持项监督。不夸称辅助监督已覆盖整个模块。

GAP仍可能对路由不敏感，本改动是否改善交互必须由三组对照检验，不能因计算图连通就认定有效。

## 修改2：分组辅助梯度范数上限

在相同64图全批次上计算原GPS过滤MultiSimilarity主损失、0.1倍辅助损失和0.1倍保持项。分别用原微批梯度重放求梯度，再按模块一级参数名前缀分组：

`s_b = min(1, 0.5 * ||g_main,b|| / ||g_aux,b||)`

`g_b = g_main,b + s_b*g_aux,b + g_keep,b`

辅助梯度为零时scale=1；主梯度为零而辅助不为零时scale=0，不添加保底更新。保持项不变。组合后只进行一次原全局clip=1，再AdamW更新。每步记录各组原始/截断梯度范数及scale；检查截断辅助范数不超过主范数50%。

这是分组梯度控制，不是把辅助标量损失统一乘一个动态系数，也不是PCGrad或已有理论创新性的证明。梯度范数受模块维度、参数化影响，50%为预先固定的工程验证参数，不在验证集上搜索。

原零初始化output会使第一步上游主梯度为零，因此V2也会暂时抑制这些组的辅助更新；待最终output由主损失开始更新后，辅助逐步进入。真实smoke必须验证所有参数最终见到梯度且exchange实际获得非零的截断辅助梯度，不能仅验证原始梯度连通。

## 训练与比较协议

- 新目录`logs/single_dino_supervision_v2`，独立schema。只允许从冻结创新点1和原seed42随机head重新开始；不能直接续训V1融合器。
- 保持GSV8192地点、P16/K4、四视图、322、FP32、microbatch2、1024步、学习率1e-4、weight_decay=0。每16步可恢复保存。
- 将来获得启动授权后，先8步真实smoke，丢弃更新后重新初始化正式训练；随后评测GSV适配留出、MSLS-val、Pitts30k-val，不访问盲测集。
- 三组共享只读冻结DINO，新head与优化器完全独立。所有分量使用相同完整64图挖掘，不能在microbatch2内部重新挖掘。
- V1/V2预算相同但同时改变辅助读出位置和梯度控制，比较只能归为“监督修正组合”，不能分别宣称两个改动各自有效；V2内三组用于检验对齐交互是否优于独立和打乱。
- 逐分量梯度重放比V1更费计算，不能用V1约50分钟的训练时长直接承诺V2时长。实际效率需启动后测量。
